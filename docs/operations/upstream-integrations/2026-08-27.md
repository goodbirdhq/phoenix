## Defects found in clean auto-merges

These merged without a textual conflict and were all broken:

1. **Contracts import cycle.** Phoenix added `orchestration.ts → providerRuntime.ts`;
   upstream added `providerRuntime.ts → orchestration.ts`. Neither is cyclic alone.
   Combined, `ProviderApprovalOption` was `undefined` at module-init and every
   contracts consumer threw at import. Typecheck could not see it. Fixed by moving
   the Phoenix-owned `ProviderRuntimeErrorKind` into `baseSchemas.ts`, the leaf both
   already import.
2. **Version-skew hint.** Phoenix brands the mismatch hint "Phoenix version"; the
   merged test's shared constant said "T3 Code version", so upstream's new semver
   tests asserted against the wrong string.
3. **`activeTurnInProgress` removed.** Upstream deleted the prop and its producer;
   Phoenix's retry rows read it to tell "reconnecting" from "recovered". Restored as
   an optional prop defaulting to a settled turn.
4. **`activityKind` → `sourceActivityKind`.** Upstream's rename; Phoenix's retry
   terminal-error detection kept the old name and silently never matched.
5. **Spawn-CTA visibility.** Upstream's new grouping treats a row as foldable when
   `agentSpawn === undefined`, which misses Phoenix's spawned-session and Schedule
   receipts. Unified all three call sites on `workEntryIsSpawnCta`.
6. **Test fixtures.** Upstream's new thread-row fixture lacked Phoenix's
   `spawnedByThreadId`/`reportDelivery`; Phoenix's schedule fixtures lacked upstream's
   `unsettledAt`; Claude SDK callbacks gained a required `requestId`; the handoff
   brief's `ProviderService` mock lacked `uploadFeedback`.
7. **`ProviderService` bound unconditionally in tests.** Phoenix takes the service
   optionally and falls back; binding upstream's mock by default routed availability
   through unimplemented stubs. Now bound only when a test asks for one.
8. **`ProviderUploadFeedbackError`.** Phoenix's optional-service branch failed with a
   bare string, which broke the RPC handler's error channel. One error there degraded
   `runServerCommand`'s inferred context to `any` and produced 184 downstream
   diagnostics across the server package.
