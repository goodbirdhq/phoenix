## Semantic merge decisions

- Preserved Phoenix identity, state paths, URL schemes, desktop IDs, and package behavior while
  adopting upstream implementation changes. Upstream source attribution remains where intentional.
- Kept Phoenix session orchestration and sidebar hierarchy beside upstream browser-access settings.
  The shared Phoenix MCP transport is always attached; preview and session capabilities are now
  authorized independently on every invocation.
- Preserved Phoenix reports while adopting upstream's bounded activity hydration and receipt fixes.
- Kept the new remote-editor behavior while correcting browser dispatch semantics so successful
  custom-protocol handoffs do not show a false failure.
- Restored Phoenix's mobile version `1.0.3`; upstream's `1.0.4` is not a Phoenix release decision.
- Quarantined upstream EAS production automation until Expo ownership, project/update URLs, and
  signing identities are Phoenix-owned. Removed upstream npm `t3` publication from the Phoenix
  desktop release graph.
- Disabled npm-based server self-update advertisement, execution, pinned-runtime downloads, and
  manual update commands until Phoenix owns a verified package distribution.
- Disabled npm-based Remote SSH provisioning and moved its remote runtime state to `~/.phoenix`.
  Development builds may still launch an explicit source-built server entry point; packaged builds
  fail with source-build guidance instead of executing upstream's `t3` package.
- Removed npm package-runner suggestions and disabled background-service install/update commands and
  onboarding until Phoenix has an owned distribution. Existing services can still be inspected and
  uninstalled.
- Excluded upstream AUR publication while retaining packaging sources as reference material.
- Adopted upstream desktop update behavior while directing release notes to
  `goodbirdhq/phoenix`.
- Aligned the server's desktop renderer origin allowlist and Clerk/passkey documentation with the
  registered Phoenix `phoenix://` protocol and `com.goodbird.phoenix` bundle identity.
- Hardened the mobile pairing helper by validating custom URL schemes and allowing Android to route
  through the registered scheme instead of a hard-coded development package.
- Replaced the vulnerable ASAR dependency path's `brace-expansion@1.1.15` with `1.1.18`.
