# Sales is a client of the birdhouse sales engine

Phoenix's Sales area is a client of the birdhouse sales engine, configured per Environment by URL and tokens, not a generic adapter: the sales contracts mirror the engine's API (`engine/docs/sales-api.md` in goodbirdhq/birdhouse), and engine vocabulary such as Slack, Notion and draft kinds appears in contracts, client-runtime and web. Phoenix stores no sales records; Notion and the engine remain the truth. The server polls the engine only while a client is subscribed, keeps the latest answer in memory, and streams it to clients, so every client and connection mode sees the same data without reaching the engine itself. Knowledge of which birdhouse skills to dispatch, and how, is confined to `apps/server/src/sales/SalesDispatch.ts` for now; moving it to dispatch plans the engine supplies is tracked in Linear. Naming the coupling keeps it honest: a second engine would mean a real abstraction, not a swap behind an existing one.
