# Sales is a client of the birdhouse sales engine

Phoenix's Sales area is a client of the birdhouse sales engine, configured per Environment by URL and tokens, not a generic adapter: the sales contracts mirror the engine's API (`engine/docs/sales-api.md` in goodbirdhq/birdhouse), and engine vocabulary such as Slack, Notion and draft kinds appears in contracts, client-runtime and web. Phoenix stores no sales records; Notion and the engine remain the truth. The server polls the engine only while a client is subscribed, keeps the latest answer in memory, and streams it to clients, so every client and connection mode sees the same data without reaching the engine itself. Which birdhouse workflows to dispatch, and the prompts that start them, are the engine's: it sends a dispatch plan for each run it offers, and Phoenix only fills in the note and starts the thread. Naming the coupling keeps it honest: a second engine would mean a real abstraction, not a swap behind an existing one.
